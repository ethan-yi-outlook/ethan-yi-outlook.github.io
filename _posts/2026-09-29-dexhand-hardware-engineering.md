## 前言

灵巧手是自由度最高的机器人末端执行器，也是约束最密集的一个：**机械传动、电机驱动、实时总线、触觉传感、量产工艺**五个系统同时压在只有手掌大小的空间里。任何一个环节没想清楚，最后都会以「腱绳断了」「传感器没数」「装配装不回去」的形式在产线上暴露出来。

这篇笔记把过去两年做五指灵巧手（DexHand 021 / 021S / 021Pro）、穿戴式数采外骨骼（DexCap）与手持数采夹爪过程中积累的工程细节整理成一份可查的清单。**每个数字都来自真实测试或产线记录，每个坑都对应一次真实的返工。**

> 本文为个人技术复盘笔记。为保护合作方与同事隐私，已隐去全部人员姓名，并对供应商/客户信息做泛化处理；技术参数与测试数据保持原值。

## 一、产品矩阵：三层结构

同一套 SDK、嵌入式平台、供应链与工厂，支撑起三条不同定位的产品线：

| 层级 | 产品 | 定位 | 状态 |
|---|---|---|---|
| **数采设备层** | DexCap 外骨骼 | 穿戴式双手遥操作数据采集 | V4 批量交付 |
| | 手持数采夹爪（UMI 方案） | 手持示教，采 6DoF 轨迹 + 触觉 | DVT3 |
| **机器人整机层** | 半人型平台 | 遥操作数采载体（数采 3.0） | 联调中 |
| | 小默 / 大默双臂平台 | 移动底盘 + 臂 + 手 + 语音一体机 | 一期结题 |
| **灵巧手层** | DexHand 021 | 五指 · 腱绳驱动 | 已量产 |
| | DexHand 021S | 三指 · 成本优化 | 代工量产（MP） |
| | DexHand 021Pro | 五指新一代 · 触觉 + 推杆 | PVT1.1 |
| | 021Lite | 客户定制轻量版 | 现场联调 |

**一条数据主线**：所有产品最终服务于同一条数据链——外骨骼 / 手持夹爪 / 半人型采集 → `rosbag` → HDF5 / Lance → 模型训练。硬件不是为了卖硬件，硬件是为了让数据的「采集精度」和「采集规模」同时成立。

**研发—工厂双轨**：上海侧负责设计、图纸、SOP、固件与关键组件装配；自有工厂负责来料检、装配、测试、包装与返工；三指线另由外部代工厂量产。

## 二、DexHand 021Pro：五指灵巧手硬件架构

### 2.1 构型与传动

采用「4 指 + 拇指」构型，**腱绳—滑轮传动为主、局部引入直线推杆**：

- **四指**：腱绳 + 导轮传动。每指近端由 2 个电机驱动、远端 1 个电机；「远近端三个马达一起使能」时可达最大负载。
- **拇指**：3 个电机独立驱动，钢丝绳预紧力可调。
- **传动链**：电机绞盘 → 腱绳 → 导轮 → 指节。
- **传动效率**：按 **60~70%** 核算。这是个关键修正——最初按 80% 预估，实测后打了七折，直接改变了负载指标的定档。

效率的影响可以量化：长 7mm 电机按 80% 效率推算关节力矩 368 mNm，末端静态拉力约 300~400 g。**传动效率是灵巧手负载上限的第一性约束**，它比电机选型本身更值得先算清楚。

### 2.2 电机与驱动

电机选型走了三代：

| 阶段 | 方案 | 关键参数 | 问题 |
|---|---|---|---|
| 早期 | 微型直流电机 | 限速 32000 rpm；连续极限 600 mA，一般 400 mA，推荐额定 200 mA | 堵转发热严重 |
| 四指 | 国产混合式步进伺服 | 额定 146 mNm，厂商称连续 240 mNm，极限可 1.5× 额定 | 需配合减速比设计 |
| 后期 | 直线推杆（内置驱动器 + 力传感器） | 行程 0~35 mm，最大力 500 N | 反电动势影响供电上限 |

控制模式上支持两类：早期用 **03hall 广播协议**（多电机同帧下发），后期拇指远端用 **44 模式**。

**堵转保护**是个反复踩的坑：默认允许堵转 200 ms，测试时放宽到 2000 ms。026Pro 后期连续 4 台复现堵转异常，最终定位根因是**下位机固件没按版本更新**——不是硬件坏，是版本不一致。

### 2.3 电控与通信

- **主干总线**：EtherCAT（自研通用主站实现）+ CAN。
- **控制模式**：CSP（位置同步）/ CST（力矩，控制字 `6071`）/ CSV（速度同步），遵循 CiA402 协议族。
- **供电**：整手 **48 V 无 DC/DC 稳压**，靠 PWM 降压产生 24 V / 12 V 供马达。推杆的反电动势让 55 V 可行、60 V 就不行——供电上限是被电机反电动势卡住的，不是被电源卡住的。
- **实时性**：控制抖动的**主因是实时内核隔离问题**，而不是 PID 参数。这类问题必须从内核调度层面解决。C++ 实现封装成 Python 可调用模块，方便算法侧直接调用。

### 2.4 结构与材料

- **手掌含外壳总宽 87.5 mm**（设计目标 < 90 mm）。
- 主控板 83 × 72 mm，上表面 3.5 mm、下表面局部 1.5 mm。
- 背壳从 **POM 改为铝合金**：POM 散热差，铝合金可再减 2 mm 并实现被动散热。
- 轴件用 **h8 公差**配合。
- **腕部空间仅容 58 × 58 mm 电路板**——这是整机集成里最紧的一处约束。

### 2.5 负载与温升实测

实测数据比规格书更能说明问题：

| 测试项 | 结果 | 判定 |
|---|---|---|
| 单指远端最大负重 | 900 g（无法保持）/ **450 g（可保持）** | 需提升 |
| 远近端同时 | 1400 g（无法保持）/ **800 g（可保持）** | 需提升 |
| 空载温升 | 400 mA 连续 50 分钟，最高 44 ℃ | 可接受 |
| 待机（拇指驱动板 400 mA） | 30 分钟超 80 ℃ 触发保护 | **待解决** |
| 寿命测试 | 71 小时；**MTBF ≈ 9 h / 4500 循环；2.4 万次腱绳断裂** | 远优于早期样品 |

最后一项值得展开：早期样品的腱绳在 **1000 次**循环就断了，改进后到 **2.4 万次**——提升了 24 倍。但 MTBF 9 小时对整个系统的可靠性来说仍然是短板，这是腱绳传动路线的固有代价。

## 三、触觉传感器

### 3.1 方案选型与布局

调研过三类方案：柔性压阻式指腹传感器、AI 触觉传感器、以及自研弧面指尖方案。最终量产采用国产柔性压力触觉模组，指尖 / 指腹 / 掌面三处布点。

**数据接口规格**：

- 021Pro：五指尖各 **2 个 id、每 id 30 组数**；掌心 **4 个 id、每 id 24 个数**（可补零对齐到 30 位）。
- 手持夹爪：压力采样协议为 **120 个 int16**（有效 116 → 108 点），串口 **921600** 波特率，命令以 `0x5A` 开头。
- 角度传感器走 I2C，**单地址不可改**，双传感器并板需 6 pin 接口。

### 3.2 「应力残余」：核心缺陷与对策

这是触觉落地最典型的机械耦合问题：

> **现象**：初始无数值 → 按压后松开，数值持续存在 → 在传感器周围按压一下，数值才消失。

根因不在传感器芯片，而在**软胶套与传感器的装配方式**——受力后被胶层「记住」了。

| 对策项 | 从 | 到 |
|---|---|---|
| 硅胶套配合 | 紧配 | 松配 |
| 固定方式 | 双面胶 | 胶水 |
| 指腹胶套 | 常规 | 更松 |
| 硅胶硬度 | 40 度 | 20~30 度 |
| 脱落问题 | — | 指尖胶套改半包围涂胶 + 传感器壳加螺丝 |

注意硅胶硬度的取舍：**更硬会降低敏感度**，更软则结构支撑不足。40 度降到 20~30 度是敏感度与寿命之间的折中。

### 3.3 开启力：另一个被低估的约束

触觉传感器有一个「不出数」的阈值——**开启力**：

- 手持夹爪侧争论最久：7 g vs 10 g 两套阈值，最终拉齐到 **10 g**。
- 凸点胶条定为 **25 g / 20 mm²**。
- 实测教训：15 g 作用在 1.76 mm² 接触面上时，只有 **3/10 的概率**能出数据。

**开启力不能只看供应商规格书，必须按毫米级接触面积实测标定。** 阈值定高了，弱力交互（轻捏、滑动）全部丢失；定低了，误触发无法收敛。

### 3.4 力值化

PVT 阶段触觉**只有无量纲显示**，必须导入力值显示才有可用性。这是触觉从「有没有接触」走向「接触力是多少」的门槛，而难点是：

> 「力的精度会比较差，每个手指灵敏度不一致。」

灵敏度不一致意味着标定工作量随指数量线性增长——五指的触觉标定是五套独立标定，不是一套参数通用。

## 四、固件、SDK 与接口契约

### 4.1 固件版本管理

| 产品 | 版本线 |
|---|---|
| 021S | 主固件 `V1.1.8`（旧主板 `V1.1.4-26071`）；上位机 `V1.0.2` |
| 021Pro | `1.1.5`（生效新关节角度范围，DVT1/2 不可升级）→ `1.1.6`（力相关测试）；控制固件 `V1.0.2_Test` |

**硬性预防措施**（都是被事故逼出来的）：

1. 来料检验增加**驱动板下位机版本号检查**；
2. 验收记录表增加版本号确认项；
3. 线材必须用**线序测试仪器**（不能用万用表）并定死 A/B/H/L 测试项。

### 4.2 ROS2 话题契约

对外集成的本质是「接口契约」——话题名、维度、命名规则任何一项含糊，客户就会踩坑：

| 话题 | 数据规格 |
|---|---|
| `/camera/*/image_raw/compressed` | 全局 RGB / 深度 / 左左手 / 右手 / 双目；要求单相机 > 1280×720 |
| `/left_arm/joint_positions` | `[T, 7]`，7 关节机械臂 |
| `/left_hand/joint_positions` | `[T, 20]` 关节位置反馈（命令侧 4 个补 0） |
| `/left_hand/joint_states` | `motor_torque` / `motor_hall`（电机端编码器）/ `motor_velocity` / `motor_current`；臂 `[T,7]`、手 `[T,16]` |
| `/control_states` | `motor_controlword` / `motor_statusword` / `motor_errorcode` |
| `/left_hand/touch_sensors` | 触觉点阵：`thumb_p0_1`、`fingers_p1_7`…，每键 30 个数 |

### 4.3 错误码机制

> 「错误码连续主动清错次数不超过 10 次，每次 1 秒，超 10 次需指令动作清错，防止设备损坏。」

这条设计很有意思：**自动清错是给偶发故障的容错，但必须有限次**——否则真实的机械故障会被无穷次自动清错掩盖，最后以硬件损坏收场。

### 4.4 交付物清单

一期结题的对外交付定义得很清楚，四项缺一不可：

1. SDK 使用说明书（环境 / 模型 / 操作 / API / 注意事项）
2. URDF + MuJoCo 模型
3. 代码 + README + 仓库链接
4. 运行结果证明（**视频 + 数据**）

## 五、DexCap：穿戴式外骨骼数采系统

### 5.1 产品定义

用「异构控制外骨骼」替代传统动捕手套，让操作者在真实作业中自然采集精细手部动作。

| 指标 | 规格 |
|---|---|
| 自由度 | 双臂各 **9 DoF**（输出末端位置 + 欧拉角 + 四元数）；双手各 **20 DoF**（基于单手 21 自由度关节反馈解算）；腰部 **5 DoF** |
| 响应频率 | **> 1000 Hz** |
| 力反馈 | 每指**五级震动反馈** |
| 通信 | Wi-Fi / 2.4G / USB 有线**三模** |
| 兼容性 | 兼容主流协作机械臂 SDK（国产 / UR / Franka） |
| 续航 | 按键续航 > 10 h；实测 1.5 W 恒功率续航 **5 h 40 min**（目标 8 h） |
| 重量 | 目标 双臂 + 双手 **< 2 kg** |
| 适配 | 身高 160–180 cm；对外定位「毫米级采集精度」 |

### 5.2 硬件与嵌入式

- **手部 21 通道角度传感**：固件定义完整枚举 `SENSOR_DATA_SIZE = 24 uint16`（5 拇指 + 4×4 四指 + recv/status）。
- **数据传输技巧**：原始数据是电压（最大 5 V），统一按「原始值 × 10000 的 uint16」回传——**避免 float 在 UDP 传输中丢失精度**。这是嵌入式通信里的经典取舍：宁可自己定标，也不要依赖浮点协议的实现一致性。
- **错误回包**：发指令出错回 `0xEE 0xEE 0xEE` + `device_id` + `channel_id`。
- **功耗**：单个传感器 0.075 W，21 只合计 **1.575 W**；舵机 5 个（每指 1 个）驱动五级震动反馈。

### 5.3 结构工程取舍

**降本路径「机加工 → 3D 打印」实测失败**，这个案例值得记下来：

- 树脂件孔轴配合**掉粉**；
- 初期过盈、后期**间隙变大**（蠕变）；
- 换尼龙后**丝级公差达不到**。

**最终定案：核心传动件机加工 + 其余 3D 打印。** 降本不是全线替换材料，而是按零件的公差敏感度分级。

另外，手部尺寸在实测后做了修正：小拇指 +8 mm，无名指 / 食指 / 拇指 +10 mm，中指 +12 mm。**纸面人因数据必须用真人实测校准。**

重量演进：旧版单手 267 g → V2 340 g → V4 单手带电池 **0.357 kg**，上肢净重 3.9 kg。功能增加必然增重，减重只能靠材料与结构迭代。

### 5.4 软件与数据链路

- 全栈走 **ROS2**：先定数据格式与通讯方案，再打通链路。
- **手部基坐标系 = 臂末端坐标系**，要求「装配到初始位置再建系」，并提供基于 DH 参数的自检脚本。
- SDK 分 C++ / Python 两套；上位机分工厂版与客户版；URDF 单独维护并版本化。
- 出口合规：说明书需包含**软件链路 / 架构**说明（报关用），通信协议英文名统一为 `data exchange protocol`。

### 5.5 NPI 试产实录

第一次批量交付只有 20 台，但暴露的问题很典型：

| 问题 | 现象 / 数据 | 根因与解决 |
|---|---|---|
| USB / 串口连接成功率低 | 5 m 线偶现识别不到；3 m 线读到端口就复现红闪；2 m 线正常 | 逐段 ABA 排查 + 示波器，判定为**信号衰减**（与手无关）→ 长期方案「网线 + 有源 HUB」 |
| 结构件裂纹 | 检验 145 个件，**44 个裂纹 > 2 mm** | 轻微件锉刀磨平（确认非贯通）→ **整批退换货重做** |
| 连杆批量不良 | Ls2 连杆 22 个 + 右 20 个 + Lx2 5 个「孔未打好」 | 评估本地加工厂补做；两批料不混用以避免色差 |
| 传感器良率 | GT-B 型号良品**仅够 35 套** | 来料检加严；关键件全检、非关键件抽检 |
| SDK 概率性异常 | 「不能上使能 / 采样后无数据」随机复现；另有 CRC 校验错误帧 | 建单复现定位；结项前阻塞类 Bug 必须清零 |

**连接率低不是「线坏了」，而是信号衰减**——用分段实验 + 示波器定位，而不是靠猜。这类「不猜、做实验」的排查方式，是硬件问题定位唯一的可靠路径。

## 六、量产：NPI 流程、供应链与工艺

### 6.1 阶段流程与节点

严格遵循 **BB/DVT → EVT → PVT → MP** 的阶段流程，每阶段有提测模板、版本号规范（如 `V1.00_20251231`）与验收记录表。

| 型号 | 关键节点 |
|---|---|
| 021 | BB2.0 样机 → DVT0/DVT1 → 25 只生产 / 35 套备料 |
| 021S | DVT1 试装 6 → 12 台 → **45 只试产转 MP** → 累计订单备料 90 只 |
| 021Pro | DVT4（固件 7 个 Bug 待关）→ **PVT 共 55 套备料**（PVT1.1 20 只）→ 交付 3 只整手 + 2 个拇指 |

**NPI 的胜负手是「物料齐套 + 固件冻结 + 工装就位」三线并行。** 021Pro 的教训很典型：DVT4 已开线，但固件还有 7 个 Bug 未关；腱绳组件需提前 3 天组装（四指 17 号开工 → 20 号才能装单指）——**排产必须按最长工序倒推**。

### 6.2 供应链与交期

**关键件交期最长 35 天，研发转量产需提前 1.5 个月下单。** 供应链是量产节奏的真正节拍器。

| 物料类别 | 方案要点 |
|---|---|
| 电机 | 步进伺服（配合减速比）；低成本舵机（三指线）；堵转与发热是选型核心考量 |
| 直线推杆 | 内置驱动器 + 力传感器，行程 0~35 mm |
| 腱绳 | 从 0.75 mm → H190 → **H185（外径 0.69 mm）**；极限拉断强度 570~600 N；**左洋红 / 右蓝**做颜色标记区分左右手 |
| 结构件 | 注塑、涡轮、机加工分供应商；主力机加工厂 1 家 |
| 摄像头 | 国产 USB 模组，从 100 万 → 500 万像素 |
| 标准件 | 磁铁（3×3 径向）、螺丝、轴承 / 卡簧 / 圆柱销 |

**典型来料问题**（每条都对应一次停线）：

- 圆柱销 Φ2×12 **生锈**导致滑轮不能转动；
- 螺钉料号缺失导致仓库清点困难；
- 主控板不良率偏高；
- **送货单与实收不符**（84/80、86/80、60/55）；
- 摄像头装反、无防呆设计；
- 拇指关节 0 空位超差，10 PCS 全退。

**整改**：试产阶段所有物料全检 → 正式阶段关键件全检、非关键件抽检；出货标签统一 `P/N + 描述 + 日期 + 数量`。

### 6.3 工艺与工装

整手 = 单指 × 5（或三指 × 3）+ 手掌 / 四指 + 整手总线。装配高度依赖工装精度与手感：

**工装夹具清单**：拇指磁铁安装治具、拇指电机绞盘压线盖、零位工装（因对拇指限位不牢，改为新四零件工装）、单指测试工装、成品测试工装、手抓壶铃测试工装、电机蜗杆组装治具、磁铁压入工装。

| 工序 | 参数 / 要求 |
|---|---|
| 点胶 | 摄像头镜头点胶固定；传感器固定从双面胶改**胶水** |
| 腱绳压接 | 钢丝绳二次加工（锻压 / 压接）；工厂先压好圆套、**不切毛边**（绞盘版本不同切除量不同） |
| 标零 / 标定 | 工装锐边需锉平；**夹爪夹紧状态为零位**，一般校准一次 |
| 润滑 | 弹簧槽内全部加润滑油（解决异响） |
| 老化 / 寿命 | 老化测试 30 次；寿命测试 12 万次（2.5 kg 标称负载） |
| 包装 | 按刀模制作，跌落测试 OK；含整手 + 航插线 + 电源 + CANFD 盒 + 检测报告 |
| 阻燃 | 低压产品用 V1 级阻燃外壳即符合中/欧/美大部分要求；外观注塑件不带电可不做 |

一个细节：三指线追加的三项 SOP 是——① 装角度传感器前做单指**重力回位确认**；② 齿轮 T 型销装配后**整圈确认无堵塞**；③ 钢丝绳与绞盘连接处**加热熔胶限位**。

**SOP 里每一条「看似啰嗦」的规定，都对应一次真实返工。**

### 6.4 质量与不良分析

| 不良模式 | 比例 / 现象 | 根因与改善 |
|---|---|---|
| **腱绳脱落 / 滑落** | 3 只整手 + 2 拇指全中（核心不良） | 根因：滑轮外径与圆柱销尺寸**双双走下差** → 换料后 30 次测试未复现；措施：物料隔离 + 改公差 + 全图纸 release |
| 腱绳磨损 / 毛刺 | 老化 30 次后远指端明显毛刺 | 卡槽毛边刮腱绳；单指测试摩擦轨迹不经过弹簧（待复核） |
| 单指根部左右摆动 | **25%**（20 只中 5 只） | 左右动作不同步 → 需固件层面调整 |
| 主控板不良 | 不良率偏高 | 四指 / 拇指主控板测试新增 3 个问题点 |
| 44 模式堵转 | 连续 4 台复现 | 根因：**下位机固件未按版本更新** → 来料检增加版本号检查 |
| 上位机报错 | 概率约 **50%** | 上位机报错 / 卡顿死机 → 新增 3 个软件问题点 |
| 传感器数据跳动 | 我方万级 / 客户十万级 | 客户侧读数差异，随断腱绳问题一并写入说明书 |
| 摄像头装反 | SOP 出线示意图有误 | 改用 500 万像素模组；摄像头盖气泡以**限度样品**为准 |
| 磁铁过零 | 影响角度读数 | 工装磁铁角度调整 20° |
| 划伤 / 掉漆 | 标定工装、老化测试导致外管划伤 | 工装锐边锉平；表面处理工艺改善 |

**分析方法论**：把「现象」定位到「尺寸链 / 固件版本 / 装配手法」。腱绳脱落看似装配问题，实为**两个零件公差的叠加**（滑轮外径 + 销轴同时下差）；堵转看似硬件故障，实为**固件版本未同步**。定位到根因后，改善才是可复制的。

### 6.5 认证

- **RoHS**：曾报铅超标（特定焊锡型号），改无铅后通过。
- **CE-LVD**：要求外壳阻燃 ≥ HB 级，建议增设阻燃料。
- **温升保护**：电机无温度传感器，过温不能及时报错；曾出现单指堵转导致马达温度熔掉 3D 打印外壳。

## 七、行业标准参与

参与《人形机器人 部组件 灵巧手技术规范》（行业标准草案）的编写，承担**第六章**。

讨论中的几个分歧点很有代表性：

| 条款 | 结论 |
|---|---|
| 动力学指标 | 动力学计算 ≤ 1 ms、逆动力学 ≤ 2 ms |
| 运动学正逆解 | 一度被认为「属代数计算、很简单」，最终 9-04 确认纳入 |
| URDF | 经讨论放入**附录**（实现细节不宜入正文） |
| 电气接口 | 争议最大。有厂商建议写死自家接口，但被否——理由：「**既然是标准，就有普适的要求，限死就是针对他自己的产品**」 |

标准制定中的核心原则是 **普适性优先**：不能把某一家产品的私有接口（特定电压、特定总线协议）写死成行业标准。

## 八、工程总结

回头看，灵巧手硬件的核心矛盾始终是 **「性能指标 vs 量产良率 vs 成本」三角**：

1. **传动效率是第一性约束。** 80% 的乐观预估修正到 60~70%，直接改变了负载定档。所有下游指标都应该重算一遍。
2. **触觉的瓶颈在机械耦合，不在芯片。** 胶套硬度、装配方式、开启力阈值——这三项决定了读到的是「应力残余」还是干净信号。
3. **接口契约要和硬件一起交付。** 话题名、维度、命名规则、错误码行为、版本号，任何一项含糊都会变成客户的集成事故。
4. **不良分析要落到尺寸链和版本号。** 「腱绳断了」和「堵转」都不是终点，公差叠加与固件版本才是。
5. **量产节奏由供应链和模具周期决定。** 关键件 35 天交期、模具 40 天周期——研发决定转量产的那天就必须下单，晚一周整体顺延。
